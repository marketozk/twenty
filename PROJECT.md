# Twenty CRM: общение с клиентами вместо SaleBot

Дата фиксации: 26.10.2026 (Москва).

Цель: сделать Twenty единым рабочим местом для общения с клиентами Telegram/MAX, CRM, автоматизаций и ИИ. В конечном решении SaleBot не требуется для работы переписки. По последнему уточнению пользователя тендерный робот и интеграция с ним не входят в проект.

Уточнение 26.10.2026: несколько менеджеров с отдельными входами и правами могут участвовать в одном клиентском диалоге; ИИ должен иметь максимальные прикладные полномочия внутри CRM по установленным правилам. Основной вариант каналов — существующие юзерботы Telegram/MAX; они остаются транспортом сообщений.

## Код и репозитории

Эта папка — локальная копия нашего форка: https://github.com/marketozk/twenty.

- `origin` — `marketozk/twenty`, наши изменения.
- `upstream` — `twentyhq/twenty`, исходный проект.
- Начальная ревизия форка: `729f6236126eddaa68d176fb766bc349b19de11d`.
- Эта же ревизия принята как база разработки 2.52 по просьбе пользователя; [перечень SHA](Research/omnichannel_crm/upstream-2.52.json). Все её исходники уже присутствуют, повторный cherry-pick не нужен. Это снимок разработки, не опубликованный релиз и не версия работающего демо.
- Ветка постановки задачи: `codex/omnichannel-requirements`.
- `packages/` — исходники Twenty; структура upstream сохранена.
- `Research/omnichannel_crm/` — постановка задачи и дальнейшие исследования/проектирование.

Новый код этой доработки размещается в этом проекте. Архитектура v1 выбирает модули `omnichannel` в twenty-front/server/shared и отдельный транспорт. Каноническая переписка остаётся в Message/MessageThread Twenty. Эти модули пока спроектированы, а не реализованы.

Исходники существующих Telegram/MAX-коннекторов пока остаются в их прежних проектах. Перенос или выделение нужных частей должен сохранить лицензии, историю и границы сервисов; копировать весь старый проект вместе с конфигами, сессиями и данными нельзя. Сейчас эти компоненты не перенесены и не изменены.

## Текущее состояние

Выполнено: создана папка на Рабочем столе, скачан исходный код нашего форка, записаны требования и предварительный план. Проведено исследование исходников Twenty, Telegram/MAX-коннекторов и API робота; результаты и границы проверки находятся в `Research/omnichannel_crm/research.md`. Клон содержит исходники выбранной ветки, история Git первоначально загружена с глубиной 1. Поддержка длинных Windows-путей включена локально для этого репозитория.

Демо обновлено с официального образа 2.50.0 до 2.51.0 по отдельной просьбе пользователя; проверки и резервная копия перечислены в отчёте обновления. Маршруты сообщений SaleBot не переключались. Исходники форка по-прежнему указывают 2.52.0: ветка разработки и установленный стабильный релиз различаются.

Зафиксированы архитектура v1 и технический план: модуль в форке Twenty, отдельные юзерботы/коннектор, единая отправка, APP messaging storage, scoped ИИ, импорт и собственный аудит действий. Выбрана собственная реализация нужных коммерческих функций без подписки Twenty. Требования обновлены до v0.6. Не выполнены разработка чатов/прав/аудита, установка зависимостей и сборка/деплой нашего изменённого кода. Обновление официального образа не означает реализацию проекта омниканальной CRM.

Выполненный разрешённый объём: фиксация требований, подготовка проекта, исследование, обновление демо до 2.51 и принятие полного снимка 2.52 как базы нашего кода. Проверено наличие 14 выбранных изменений в форке; уточнён существующий APP API приёма внешней переписки. Тесты приложения и сборка нашего снимка пока не запускались. Порядок дальнейшей работы — Design → Plan → Review → Implement. Полнота нужной функциональности не заменяется обещанием выпустить только ИИ-черновики или только Telegram.

Установка и команды upstream находятся в [README.md](README.md) и [CLAUDE.md](CLAUDE.md). Они здесь не выполнялись. [Инструкция разработки приложений](packages/twenty-docs/developers/extend/apps/getting-started/quick-start.mdx) поддерживает macOS/Linux и рекомендует WSL 2 на Windows. Папка на Рабочем столе — место исходников и документов; среду сборки и тестирования нужно выбрать на этапе исследования.
