# Без подписки Twenty: состав переиспользования и собственных функций

Решение пользователя 26.10.2026: подписка не нужна; требующиеся коммерческие возможности реализуем сами. Q-10 закрыт. Это выбор способа разработки, а не команда немедленно повторить весь Enterprise-каталог.

## Проверенные условия

Исходники выбранного снимка доступны, включая файлы `@license Enterprise`. Коммерческая часть не становится AGPL-кодом из-за нахождения в публичном репозитории. [LICENSE](../../../LICENSE) отдельно разрешает копировать/изменять её для development/testing без подписки; production требует действующего коммерческого права. Изменение такого файла само по себе не превращает его в нашу независимую бесплатную реализацию.

Стандартная self-hosted коммерческая поставка активируется Organization key, а не покупкой исходников навсегда. По [условиям Twenty](https://twenty.com/terms) после окончания подписки платные функции отключаются, бесплатная часть и собственные данные сохраняются. [Инструкция активации](https://docs.twenty.com/user-guide/billing/capabilities/pricing-plans). Локально `EnterprisePlanService` читает ключ и проверяет подписанный validity token; никаких ключей/проверок в этой работе не меняли.

## Что использовать и что разработать

| Возможность | Решение для нашего проекта |
|---|---|
| CRM objects, интерфейс, кастомизация, API, apps, workflow, AI agents/skills | Переиспользовать доступную бесплатную часть по её лицензиям. [Self-hosted Free](https://docs.twenty.com/user-guide/billing/how-tos/billing-faq) включает Pro-возможности без поддержки команды. Это не означает бесплатное потребление внешних моделей. |
| Ограничения отдельных клиентов/сделок/диалогов, правила этапов | Собственная политика доступа, интегрированная во все пути чтения/изменения. Не использовать Enterprise RLS как runtime-зависимость и не превращать его копию с удалённой проверкой в «свою» реализацию. |
| Аудит действий и прикладные проверки | Собственные audit events и domain validators по требованиям CRM. Доступность платного audit UI не нужна. |
| Собственный домен / TLS | Настройка self-hosted адреса и reverse proxy. Платная привязка домена в облаке не нужна для нашего хостинга; настройка не выполнена этим документом. |
| Изолированная установка и БД | Наша инфраструктура и отдельный тестовый стек; не обещание всех условий Enterprise single-tenant offering. |
| Ограничение IP | При необходимости — правила reverse proxy/firewall/VPN с отдельным тестом доступа. Не требуется копировать Enterprise-модуль. |
| SAML/OIDC SSO, SCIM | Если понадобятся — независимая интеграция открытых IdP/библиотек с проверкой их лицензий и lifecycle пользователей. Пока не подтверждены как обязательные функции этой CRM. |
| Priority support / SLA | Услуги поставщика, не код для установки. Наши мониторинг, резервирование и обслуживание определяются эксплуатационным планом. |

Перечень не разрешает коммерческое production-использование и не меняет лицензии upstream. Разработка своих функций идёт от наших контрактов/тестов и разрешённых компонентов. Для затронутых файлов проверять заголовок, пакетную лицензию и транзитивные зависимости; тестовый доступ к Enterprise не становится обязательным для сборки или приёмки production-модуля.

## Приёмка выбранного пути

- Free/self-hosted среда без Enterprise key; реальные кейсы видимости работают через собственную политику.
- Проверены generic REST/GraphQL, relations/search/export/groupBy, SSE, файлы, workflow и AI tools; отказ до раскрытия данных.
- Нет разрешения «admin по умолчанию» при пропаже роли/связи; старые права/подписки/AI-контекст инвалидируются.
- Наш модуль не вызывает Enterprise RLS и не подменяет `isValid`/entitlement для активации коммерческого кода. Наличие неизменённых Enterprise-файлов в upstream snapshot не выдаётся за их активацию.
- Сервер, файловое хранение, поддержка и внешние AI API остаются ресурсными/эксплуатационными расходами; «без подписки Twenty» не означает нулевую стоимость всей системы.
