# LOG137 — аудит удаления переписки по блок-листу

BlocklistItemDeleteMessagesJob передаёт закрытому owner точные association IDs
страницами по 200. Внутри одной strict/exclusive транзакции повторно читаются
правила, область действия, текущая связь сотрудника с аккаунтом, адреса канала
и participants. Выборка, удаление зависимостей и аудит используют один executor.

Сохраняется прежняя политика: точный адрес сравнивается с учётом регистра,
домен — PostgreSQL ILIKE с прежними wildcard/escape правилами; собственный
адрес и aliases исключаются только для доменного условия. Роли берутся из
существующей константы Twenty. NULL/empty externalId не меняет отбор по ID.
Защищённый канал первоначально пропускается; позднее изменение источников
откатывает собственные изменения и аудит.

Общий orphan sweep после страниц остаётся отдельной аудируемой операцией.
Это сохраняет прежнее поведение, но не означает атомарность всего задания.
