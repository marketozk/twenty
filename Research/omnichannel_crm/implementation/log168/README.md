# LOG168 - аудит жизненного цикла `twoFactorAuthenticationMethod` и операций восстановления `redeemRecoveryCode`

Проверки доработки завершены. ROB765 остаётся In Progress.
[Дизайн](design.md), [ревью решения](design-review.md), [ревью кода](review.md), [план проверок](test-research.md).

LOG168 закрывает транзакционный аудит создания, ротации, верификации, удаления и замены методов двухфакторной аутентификации (`core."twoFactorAuthenticationMethod"`), а также пакетного отзыва `core."appToken"` (`RefreshToken`) при погашении кода восстановления (`TwoFactorAuthenticationRecoveryService.redeemRecoveryCode`). Подключены `TwoFactorAuthenticationService` (`initiateStrategyConfiguration`, `validateStrategy`, `verifyTwoFactorAuthenticationMethodForAuthenticatedUser`, `deleteTwoFactorAuthenticationMethod`), `TwoFactorAuthenticationResolver` (`initiateOTPProvisioning`, `initiateOTPProvisioningForAuthenticatedUser`, `verifyTwoFactorAuthenticationMethodForAuthenticatedUser`, `deleteTwoFactorAuthenticationMethod`) и `TwoFactorAuthenticationRecoveryService.redeemRecoveryCode`.

В `crm-audit-transaction-context.ts` разрешены действия `['create', 'update', 'delete']` в `ADMINISTRATIVE_ACTIONS.twoFactorAuthenticationMethod`, а поле `secret` добавлено в `CATALOG.twoFactorAuthenticationMethod.redacted` (в событиях сохраняется только безопасный маркер `{ redacted: true }`, хеш `secret` отслеживается в `changedFields` при ротации просроченного `PENDING` метода, обратная совместимость с `membership-cleanup-audit.ts` сохранена). Создан модуль `two-factor-authentication-audit.ts` (`captureTwoFactorAuthenticationAudit`, `runAuditedTwoFactorProvisioning`, `runAuditedTwoFactorValidation`, `runAuditedTwoFactorDeletion`, `runAuditedTwoFactorRecoveryRedemption`, регистрация в `registerMetadataAuditScopeCheck`), который захватывает идентичность синхронно до первого `await`, удерживает эксклюзивную блокировку `acquireUserAuthenticationLock` и блокировки `core.workspace` / `core."userWorkspace"` (`FOR NO KEY UPDATE`) и целевых строк `core."twoFactorAuthenticationMethod"` / `core."appToken"` (`FOR UPDATE`), проверяет резервную регистрацию внутри транзакции (M2), записывает `refreshToken:update` с `tokenOwner` при пакетном отзыве refresh-токенов (M3), генерирует уникальный `UUID` для нового `PENDING` метода при обязательной 2FA (M4), не создаёт шумовых событий при повторных OTP-проверках `VERIFIED` метода (T1), принудительно отзывает пользовательские сессии при `NativeTransactionOutcomeUnknownError` / `CoreAuditPostCommitError` в `redeemRecoveryCode` (M5) и повторно сверяет снимки после `audit.flush()`.
