# LOG167 - аудит жизненного цикла и каскадного удаления `applicationAuthorization` и `userApplicationVariableValue`

Проверки доработки завершены. ROB765 остаётся In Progress.
[Дизайн](design.md), [ревью решения](design-review.md), [ревью кода](review.md), [план проверок](test-research.md).

LOG167 закрывает аудит создания, обновления, отзыва и каскадного удаления пользовательских OAuth-согласий приложений (`core."applicationAuthorization"`) и пользовательских значений переменных приложений (`core."userApplicationVariableValue"`). Подключены все сервисы и резолверы: `ApplicationAuthorizationService` (`recordAuthorization`, `backfillAuthorizationFromRefreshToken`, `revokeAuthorizationByIdForUserWorkspace`, `revokeAuthorizationForApplication`), `ApplicationAuthorizationResolver.revokeApplicationAuthorization`, `OAuthService` (`exchangeAuthorizationCode`, `refreshTokenGrant`, `revokeToken`), `UserApplicationVariableValueService.updateMyUserApplicationVariable`, `UserApplicationVariableValueResolver.updateMyUserApplicationVariable`, `ApplicationService.delete`, `ApplicationSyncService.uninstallApplication` и пакетный раннер миграций `runAuditedApplicationMetadataMigration` (`WorkspaceMigrationRunnerService.executeRun`).

В `crm-audit-transaction-context.ts` разрешены действия `['create', 'update', 'delete']` для `applicationAuthorization` и `userApplicationVariableValue`, а поле `value` добавлено в `CATALOG.userApplicationVariableValue.redacted` (в событиях сохраняется только безопасный маркер `{ redacted: true }`, как и для `scopes` в `applicationAuthorization`). Создан модуль `application-authorization-and-variable-audit.ts`, который выполняет захват контекста атрибуции синхронно до первого `await`, удерживает блокировки `core.workspace` (`FOR NO KEY UPDATE`) -> `core.application` (`FOR SHARE` / `FOR UPDATE`) -> `core."userWorkspace"` (`FOR SHARE`) -> `core."applicationVariable"` (`FOR SHARE` / `ORDER BY id FOR UPDATE`) -> целевых строк `applicationAuthorization` / `userApplicationVariableValue` (`ORDER BY id FOR UPDATE`), сверяет принадлежность внешним ключам того же рабочего пространства, привязывает актора `coreUser` / `workspaceMember` / `application` к `userWorkspaceId` при мутации пользовательских переменных, использует атомарный `INSERT ... ON CONFLICT ("userWorkspaceId", "applicationId") DO UPDATE` для OAuth-согласий (с детекцией `update` при совпадении миллисекунды `createdAt` и `updatedAt`) и повторно сверяет сохранённые строки до и после `audit.flush()`. В `application-metadata-audit.ts` добавлен захват `core."applicationVariable"` и `core."userApplicationVariableValue"` под `ORDER BY id FOR UPDATE`, аудит каскадного удаления `userApplicationVariableValue:delete` при удалении `applicationVariable`, fail-closed барьер в `WorkspaceMigrationRunnerService.executeRun` на неаудируемые удаления `applicationVariable` и проверка отсутствия оставшихся `userApplicationVariableValue` перед `ApplicationService.delete`. Ошибки `NativeTransactionOutcomeUnknownError` и `CoreAuditPostCommitError` пробрасываются без маскирования, подавляют посмертные побочные эффекты в `ApplicationService.delete` и инвалидируют кэш `userApplicationVariableValueMaps`.
