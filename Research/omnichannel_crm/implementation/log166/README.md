# LOG166 - аудит каскадного удаления и обнуления прав при удалении объектов и полей

Проверки доработки завершены. ROB765 остаётся In Progress.
[Дизайн](design.md), [ревью решения](design-review.md), [ревью кода](review.md), [план проверок](test-research.md).

LOG166 закрывает аудит каскадного удаления и обнуления записей прав (`core."objectPermission"`, `core."fieldPermission"`, `core."rowLevelPermissionPredicateGroup"`, `core."rowLevelPermissionPredicate"`) при отдельном удалении пользовательских и системных объектов (`ObjectMetadataService.deleteOneObject` / `deleteManyObjectMetadatas`, `ObjectMetadataResolver.deleteOneObject`, `ObjectMetadataController.deleteOne`, `DeleteObjectMetadataTool.execute`) и полей (`FieldMetadataService.deleteOneField`, `FieldMetadataResolver.deleteOneField`, `FieldMetadataController.deleteOne`, `DeleteFieldMetadataTool.execute`), а также расширяет fail-closed барьер в `WorkspaceMigrationRunnerService.executeRun` на неаудируемые удаления `objectMetadata`, `fieldMetadata`, `permissionFlag` и `agent`.

В `application-metadata-audit.ts` добавлены режимы `mode: 'objectDelete' | 'fieldDelete'`, `captureApplicationMetadataAuditOperation`, `bindApplicationMetadataAuditOperation` и `AUDITED_ROLE_AND_PERMISSION_CASCADE_DELETE_METADATA_NAMES`. Внутри `runInCoreAuditTransaction` захватываются блокировки в каноническом порядке `core.workspace` (`FOR NO KEY UPDATE`) -> `core.application` (`ORDER BY id FOR UPDATE`) -> 7 таблиц ролей, привязок и прав (`ORDER BY id FOR UPDATE`) -> `core."objectMetadata"` (`ORDER BY id FOR UPDATE`) -> `core."fieldMetadata"` (`ORDER BY id FOR UPDATE`). Проверяются точные инварианты удаляемых объектов и полей (включая парные обратные поля `RELATION`, все таргет-поля и обратные поля multi-target `MORPH_RELATION` и осиротевшие головные поля морф-связей `morphId`), запрет удаления кросс-приложенческих групп предикатов без каскадного удаления родителя, запрет скрытого каскадного удаления или обнуления soft-deleted строк предикатов, учёт `ON DELETE SET NULL` на `workspaceMemberFieldMetadataId` и редактирование литерального поля `value`. Состояние 7 таблиц ролей/прав и таблиц `objectMetadata` / `fieldMetadata` сверяется после `work(runner)` и повторно после `audit.flush()`. В `FlatObjectPermissionValidatorService` и `FlatFieldPermissionValidatorService` разрешено каскадное удаление прав на нередактируемых системных ролях только тогда, когда целевой объект или поле отсутствует в оптимистичных картах миграции. В `WorkspaceMigrationRunnerService.executeRun` при любом удалении `objectMetadata` или `fieldMetadata` принудительно инвалидируются кэши 4 таблиц прав и `rolesPermissions` (включая чистый `ON DELETE SET NULL` на `workspaceMemberFieldMetadataId`).
