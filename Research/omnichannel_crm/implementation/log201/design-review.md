# LOG-201 Design Review

Date: 2026-11-22
Verdict: **PASS AFTER DESIGN UPDATES** (6 Blockers, 5 Majors, 4 Minors found and resolved before implementation)

| ID | Severity | Finding | Resolution in Design & Implementation |
| --- | --- | --- | --- |
| D-B1 | Blocker | Phantom `create` audit under `READ COMMITTED` when `claimUnownedThreadForRun`/`setUpCreatedThreadsInboxState` race with `AgentChatThreadParticipantService` (missing participant advisory lock + missing `ORDER BY rs.id FOR UPDATE OF rs`). | `auditAgentChatParticipantOwnerShareWrite` acquires `pg_advisory_xact_lock(hashtextextended('agent-chat-thread-participant:${workspaceId}:${threadId}:${workspaceMemberId}', 0))` in sorted deduplicated `threadIds` order and uses `ORDER BY rs.id FOR UPDATE OF rs`. |
| D-B2 | Blocker | `AgentChatSharingService.createThread` called from `AgentInboxService` / `AgentCallerConversationService` passes recipient `ownerWorkspaceMemberId`, not the calling principal (`application`/workflow/other user), causing false initiator or ambient conflict errors. | Added optional `auditContext` (`auditOperation`, `auditImpersonatorUserWorkspaceId`, `pendingUserWorkspaceActor`, `authUserWorkspaceId`, `pendingAgentId`) to `AgentChatThreadService.createThread`, `AgentChatSharingService.createThread`, and `claimUnownedThreadForRun`. `AgentInboxService.openThread` derives attribution from ALS or `sender` (`application` / `system:agent_inbox_workflow`), never attributing to the passive recipient. |
| D-B3 | Blocker | HTTP ALS (`captureCrmAuditRequest`) carries `coreUser` (`userId`), not `workspaceMember` (`workspaceMemberId`), so synchronous comparison against `workspaceMemberId` would fail every HTTP call or skip validation. | `runAuditedAgentChatRecordShareTransaction` verifies `expectedWorkspaceMemberId` inside the transaction against `${schema}."workspaceMember"` (`FOR SHARE`, checking `userId === principal.id && deletedAt === null`) when the user principal (`actor` or `initiator` under `application`/`agent`) is `coreUser`, and by direct UUID equality when `workspaceMember`. |
| D-B4 | Blocker | `AgentChatChannelService.updateChannel` / `deleteChannel` capturing a separate `recordShare` audit would diverge from `capturedAudit` (`correlationId`, `actor`, and `pendingUserWorkspaceActor` when only `authUserWorkspaceId` is supplied). | Added non-consuming `peekNavigationMenuItemAuditAttribution(capturedAudit)` in `navigation-menu-item-audit.ts` and supported `pendingUserWorkspaceActor` / `authUserWorkspaceId` / `pendingAgentId` resolution inside `runAuditedAgentChatRecordShareTransaction`, guaranteeing one shared `correlationId` and identical principal between channel metadata and `recordShare` audit entries. |
| D-B5 | Blocker | Reading `preFlushSnapshot` fresh after `work()` would miss unaudited DML between/after steps, tracking only `createdRecordIds` missed pre-existing participant rows in a batch, and checking `session.failure` only when `recordedMutations > 0` missed latched failures on 0-mutation runs. | Maintained cumulative `expectedRows: Map<rowId, RecordShareRowProjection>` across steps (failing closed on mid-transaction drift), registered all `before` and `after` participant `recordId`s, checked `session.failure` unconditionally on every helper entry and immediately after `work()`, and verified pre-flush and post-flush snapshots against `expectedRows`. |
| D-B6 | Blocker | Existing unit test `agent-chat-thread-create.post-query.hook.spec.ts` uses non-UUID stubs, partial auth contexts, and a mock `manager` without `queryRunner`. | Updated `agent-chat-thread-create.post-query.hook.spec.ts` with valid UUID fixtures, full `UserWorkspaceAuthContext`, active mock `queryRunner`, and audit SQL support, and added it to verification. |
| D-M1 | Major | `backfillWorkspaceChatThreadOwnerGrants` runs `FOR SHARE OF member, membership` on `core."userWorkspace"`, which requires `UPDATE` privilege in PostgreSQL. | Granted `SELECT, UPDATE ON core."userWorkspace"` to runtime role in `crm-audit-agent-chat-record-share.postgres-spec.ts`. |
| D-M2 | Major | `AGENT_CHAT_CHANNEL_GRANT_LOCK_TIMEOUT_MS` is `5000ms` (not `2000ms`) and `set_config('lock_timeout', '5000ms', true)` permanently lowered the `8s` timeout for the rest of the transaction. | Saved and restored `current_setting('lock_timeout')` around `acquireAgentChatChannelGrantLocks` in `acquireAgentChatChannelGrantLocksForThreadWriteOrThrow`. |
| D-M3 | Major | Empty `threadIds` early-returns bypassed fail-closed active session check; `backfillWorkspaceChatThreadOwnerGrants` allowed omitted `recordIds`; `claimUnownedThreadForRun` lacked `threadObjectMetadataId`. | Called `requireActiveAgentChatShareAudit(manager, workspaceId)` before early returns in `rewriteThreadGrantsInTransaction`, `setUpCreatedThreadsInboxState`, and all elementary helpers; required non-empty `recordIds` in `auditAgentChatThreadOwnerGrantBackfill`; resolved `threadObjectMetadataId` in `claimUnownedThreadForRun`. |
| D-M4 | Major | Lock order inversion (`recordShare` before `agentChatThread`) in `recordMemberActivity` and unordered `FOR NO KEY UPDATE` in `moveChannelThreads`. | Added `SELECT id FROM agentChatThread WHERE id = $1 FOR NO KEY UPDATE` before `auditAgentChatParticipantOwnerShareWrite` in `recordMemberActivity`, and added `ORDER BY id` in `moveChannelThreads`. |
| D-M5 | Major | `rewriteChannelGrantsMock` in `crm-audit-agent-chat-channel.postgres-spec.ts:1366` asserts exact args (and also runs on no-op update); `rewriteAllChannelGrants` needs one shared `correlationId` across all channels. | Generated one shared `correlationId` in `rewriteAllChannelGrants` / `RewriteAgentChatChannelGrantsJob`; updated `crm-audit-agent-chat-channel.postgres-spec.ts` to assert `auditOperation` and shared `correlationId`. |
| D-m1 | Minor | Avoid adding `twenty-shared/metadata` import to `record-share-audit.ts`. | Passed `threadObjectUniversalIdentifier` as a parameter from `AgentChatChannelGrantService`. |
| D-m2 | Minor | Document that `AgentHistoryWorkspaceStorageService.run` uses TypeORM `dataSource.transaction` rather than `NativeTransactionOutcomeUnknownError` on lost COMMIT ACK. | Recorded explicitly as a known limitation in `design.md` and `README.md`. |
| D-m3 | Minor | Complete dev-seeder inventory with `seed-agent-chat-thread-inbox-state.util.ts` and note `UserWorkspaceAuthContextService` does not copy `agentId` (agent attribution flows via ALS). | Recorded in `design.md`. |
| D-m4 | Minor | Verify `principalType === 'ROLE'` and `accessLevel === 'READ_WRITE'` for ALL surviving `RULE` rows in `after` in `auditAgentChatChannelGrantRewrite` (not only newly inserted ones). | Enforced across every `RULE` row in `after` in `auditAgentChatChannelGrantRewrite`. |
