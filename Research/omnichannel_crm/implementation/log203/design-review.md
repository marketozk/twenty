# LOG-203 Design Review

Date: 2026-11-22
Reviewer: independent adversarial design review agent (`a386732fd4ddf5728`)
Verdict: **PASS after resolving all findings** (2 Blockers, 5 Majors, 4 Minors - all resolved in `design.md`, `test-research.md`, and implementation)

| ID | Severity | Finding | Resolution |
| --- | --- | --- | --- |
| B1 | Blocker | Mutable/getter `processedArgs.dryRun` could return `true` during `auditedMutation` check and `false` in `run()`, falling back to unaudited `runInWorkspaceTransaction`. | Snapshot `isMergeDryRun = Boolean(processedArgs.dryRun)` once in `CommonBaseQueryRunnerService` and pass `{ ...processedArgs, dryRun: isMergeDryRun }` into `run()`; add defense-in-depth fail-closed throw in `CommonMergeManyQueryRunnerService` if a covered non-`dryRun` merge has no `transactionScope`. |
| B2 | Blocker | `select`-RLS hiding a live child row of `idsToDelete` (or `priorityRecord`) caused `mergeRelatedRecordsIntoPriorityRecord` to miss it and let `DELETE` silently `SET NULL` or `CASCADE`-destroy it via `prepareNativeCrmDeleteEffects`. | Added live-row count reconciliation via `transactionScope.executeRawQuery` (`SELECT COUNT(*)::int ... WHERE <joinColumn> ... [AND "deletedAt" IS NULL]`) after `getMany()` for both `idsToDelete` and `priorityRecordId`; any hidden live row fails closed and rolls back the entire merge. |
| M1 | Major | Under `READ COMMITTED`, moving unlocked `SELECT` inside the transaction does not eliminate TOCTOU or lock-order inversion (`child -> parent` vs `DESTROY`'s `parent -> child`). | Added canonical `SELECT id FROM <schema>.<table> WHERE id = ANY($1::uuid[]) ORDER BY id FOR UPDATE` at the start of the merge transaction before `fetchRecordsToMerge` and `mergeRelatedRecordsIntoPriorityRecord`. |
| M2 | Major | Uppercase UUIDs passed `isValidUuid` but broke lowercase `record.id` comparisons in `run()` (`orderIndex`, `priorityRecord` lookup, `idsToDelete`). | Normalize `ids` to lowercase at the start of `run()`. |
| M3 | Major | Self-referencing relations (`parentCompanyId`) could re-write a deleted `duplicateId` in `mergedData` or fail closed in `prepareNativeCrmDeleteEffects`. | Clear self-referencing `mergedData[joinColumnName]` if it points into `idsToDelete`, and explicitly document PostgreSQL self-referencing FK fail-closed behavior (`LOG-106`) in `design.md`. |
| M4 | Major | REST `RestApiMergeManyHandler` skips `assertMergeManyArgs`, so non-array `ids`, non-string `ids` elements, or string `dryRun: "false"` could throw `TypeError` or silently run preview. | Hardened `CommonMergeManyQueryRunnerService.validate` to enforce `Array.isArray(ids)`, string UUIDs, case-insensitive deduplication, integer `conflictPriorityIndex`, and boolean `dryRun`. |
| M5 | Major | Real workspaces and `companies-merge-many` / `people-merge-many` integration specs create `timelineActivity` rows pointing to merged records, which fail closed in Phase 2a until covered. | Documented explicitly in `design.md` and `README.md` (matching `LOG-202` `M1`), including GraphQL `INTERNAL_SERVER_ERROR` vs REST HTTP `400` mapping. |
| m1 | Minor | `getRelationFieldsPointingToCurrentObject` did not filter inactive (`isActive: false`) or remote (`isRemote: true`) child objects. | Added `!objMetadata.isRemote` and effective `isActive` filter on child object metadata. |
| m2 | Minor | Non-deterministic row order in `relatedRecordsOfRecordsToDelete` before deduplication and chunking. | Sort `relatedRecordsOfRecordsToDelete` by `id` ascending before `splitRelatedRecordIdsToMigrateAndSoftDelete` and chunking. |
| m3 | Minor | Pre-existing `performDeepMerge` uses `fieldIdByName` without `fieldIdByJoinColumnName`. | Documented as pre-existing out-of-scope behavior in `design.md` to keep `LOG-203` surgical. |
| m4 | Minor | Test plan lacked `duplicateCriteria` on `task`, `select`-RLS hidden child, getter `dryRun`, uppercase UUID, REST invalid `ids`/`dryRun`, empty `mergedData`, `selectedFields` without `id`, and soft-delete trigger skip. | Added all cases to `test-research.md` and `crm-audit-public-merge.postgres-spec.ts`. |
