# Code Review LOG-198

Проведено независимое code/security-ревью всех 11 изменённых и добавленных файлов `LOG-198`. Блокеров не выявлено; все 5 Major и 4 Minor замечаний исправлены и покрыты дополнительными проверками в `crm-audit-validation-rule.postgres-spec.ts`:

1. **Major - строгая валидация принципалов в `resolveCapturedOperation` (`validation-rule-audit.ts`)**: запрещён голый `agentId` без аутентифицированного базового принципала, запрещены конфликтные комбинации `apiKey` + (`user` | `workspaceMemberId` | `application`) и `impersonatorUserWorkspaceId` + (`apiKey` | `application` | `agentId`), при одновременном наличии `application` и `user`/`workspaceMemberId` без `agentId` установлен приоритет `actor: application`, `initiator: userPrincipal`.
2. **Major - привязка side-effect `validationRule:update` к затронутым полям (`validation-rule-audit.ts`, `navigation-menu-item-audit.ts`, `application-metadata-audit.ts`)**: добавлен `doesValidationRuleReferenceAnyField(row, fieldIds, fieldUniversalIdentifiers)` и опциональный `allowedClearedErrorFieldIds` в `assertValidationRuleSideEffectUpdateInvariants`. В `navigation-menu-item-audit.ts` (`cascade`) собираются `plannedUpdatedFieldIds` / `plannedUpdatedFieldUniversalIds` и блокируются обновления несвязанных правил и сброс чужих `errorFieldMetadataId`; в `application-metadata-audit.ts` разделены `fieldMetadata:update` и `fieldMetadata:delete` для `manifest` и `objectDelete`/`fieldDelete`.
3. **Major - сохранение `impersonatorUserWorkspaceId` из ambient operation (`create-validation-rule.tool.ts`, `validation-rule-audit.ts`)**: в `ValidationRuleAuditIdentity` добавлена форма `{ operation: CrmAuditOperation; impersonatorUserWorkspaceId?: string }`, через которую `CreateValidationRuleTool` передаёт `ambientOperation` без потери поля имперсонации.
4. **Major - загрузка `flatValidationRuleMaps` при каскадном удалении объекта/поля (`workspace-migration-runner.service.ts`)**: добавлено `'validationRule'` в `permissionCascadeMetadataNames` для `hasObjectOrFieldDeleteAction`.
5. **Major - одноразовость фабрики `captureValidationRuleAudit` (`validation-rule-audit.ts`)**: добавлен флаг `issued` в замыкании, исключающий повторное получение запроса с тем же `operationId`.
6. **Minor - конфликт `update` и `delete` одного ID (`application-metadata-audit.ts`)**: запрещено одновременное присутствие одного `validationRule` ID в `plannedValidationRuleUpdates` и `plannedValidationRuleDeletes`.
7. **Minor - снимок `beforeFields` для `manifest` с FK `ON DELETE SET NULL` (`application-metadata-audit.ts`)**: `beforeFields` загружается также при `beforeValidationRules !== undefined` в батчах с `objectMetadata:delete` или `fieldMetadata:update`/`delete`.
8. **Minor - проверка типов `description`, `icon` и non-null `bindings` (`validation-rule-audit.ts`)**: усилена `assertValidationRuleRowInvariants`.
9. **Minor - детерминированная предблокировка foreign `core.application` (`navigation-menu-item-audit.ts`)**: блокировка сторонних приложений для `plannedValidationRuleUpdates` вынесена до `execute(runner)` с `ORDER BY a.id FOR NO KEY UPDATE`.
