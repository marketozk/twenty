# LOG-200: транзакционный аудит оставшихся `WorkspaceTransactionScope`-писателей `recordShare` (`ShareWithService` и `WorkflowRunRecordShareService`)

## Объём изменений
- `packages/twenty-server/src/engine/core-modules/crm-audit/native-crm-audit-transaction.ts`: добавлены `standaloneShareWithScopes`, `isStandaloneShareWithScope`, `runInStandaloneShareWithScope` (с проверкой конфликта с `withNativeCrmAuditTransaction`), `delegatedRecordShareExecutors`, `isDelegatedRecordShareAuditWrite` и `runInNativeCrmAuditScopeIfPresent` (с error latching через `runNativeCrmAuditWrite`, очередью `postFlushChecks` после `audit.flush()` и `runDelegatedRecordShareWrite`), а `getNativeCrmAuditContext(executor, objectMetadataNameSingular?)` возвращает `undefined` строго на время делегированной записи `recordShare`.
- `packages/twenty-server/src/engine/core-modules/crm-audit/native-crm-audit-record.ts` и `packages/twenty-server/src/engine/twenty-orm/repository/workspace-repository.ts`: `assertNativeCrmAuditWriteSupported` и все 12 обращений к `getNativeCrmAuditContext` в `WorkspaceRepository` учитывают `objectMetadataNameSingular` (`recordShare` при `shape.tableName === 'recordShare'`), позволяя делегированную запись `recordShare` внутри `withNativeCrmAuditTransaction` при сохранении отказа для всех прочих системных объектов.
- `packages/twenty-server/src/engine/core-modules/crm-audit/record-share-audit.ts`: добавлены `verifyWorkspaceKeyShare` (`FOR KEY SHARE`), `readRecordShareSnapshotForRecords`, `normalizeDesiredRecordShares`, `resolveShareWithStandaloneOperation` (со строгой проверкой ALS `actor`/`initiator`/impersonation), `toNativeAuthPort`, `runAuditedShareWithInsert` (Branch A внутри `withNativeCrmAuditTransaction` с общим `operationId`, `SET LOCAL lock_timeout = '8s'`, `runDelegatedRecordShareWrite` и `postFlushChecks`; Branch B в самостоятельной строгой транзакции с общим `correlationId` на `scope` и разрешением имперсонатора), `validateWorkflowRunShareSyncAuditInput` (с запретом имперсонатора для не-пользовательских акторов) и `runAuditedWorkflowRunShareSync` (`FOR KEY SHARE`, diff-план удаления/вставки с сохранением неуправляемых `MANUAL`-грантов, предварительная валидация `desiredShares`, `0` записей при идемпотентном no-op и пост-flush сверка).
- `packages/twenty-server/src/engine/core-modules/record-share/services/share-with.service.ts`, `utils/build-record-share-inputs-for-created-records.util.ts` и `utils/validate-share-with-arg-or-throw.util.ts` (`/* @license Enterprise */` сохранены): `insertRecordSharesForCreatedRecords` обёрнут в `runAuditedShareWithInsert` (включая `deleteByRecordIds` + `insertMany` + `assertPrincipalsReachRecordsOrThrow`); сравнение `principalId` и `creatorRoleId` переведено на регистронезависимую нормализацию UUID.
- `packages/twenty-server/src/engine/api/common/common-query-runners/common-create-many-query-runner/common-create-many-query-runner.service.ts` и `common-base-query-runner.service.ts`: `CommonCreateManyQueryRunnerService.run` открывает `{ commitOutcome: 'strict' }` с `runInStandaloneShareWithScope` для самостоятельных `shareWith` / вложенных create-путей; `CommonBaseQueryRunnerService` исключает `isStandaloneShareWithScope(scope)` из `createCandidate`, не ломая вложенные создания нативно-аудируемых объектов.
- `packages/twenty-server/src/engine/core-modules/workflow/services/workflow-run-record-share.service.ts`, `core-workflow-mutation.workspace-service.ts`, `packages/twenty-server/src/engine/core-modules/user-workspace/user-workspace.service.ts` и `packages/twenty-server/src/engine/workspace-manager/workspace-migration/workspace-migration-runner/deferred-action-handlers/services/sync-workflow-run-shares-deferred-action-handler.service.ts`: `WorkflowRunRecordShareService` переведён на `{ commitOutcome: 'strict' }` (default `nativeOwnershipLock: 'shared'`), diff-preserving sync (`DELETE_ID_CHUNK_SIZE = 1000`), раннюю валидацию `auditOperation`/`auditImpersonatorUserWorkspaceId` (без импорта Enterprise-типов) и проброс атрибуции из `CoreWorkflowMutationWorkspaceService`, `UserWorkspaceService` и `SyncWorkflowRunSharesDeferredActionHandlerService` (с проверкой `!queryRunner.isTransactionActive` и актором `system:sync_workflow_run_shares`).
- `packages/twenty-server/test/fork-migration/crm-audit-record-share-writers.postgres-spec.ts` (новый) и обновлённые `crm-audit-core-workflow-and-view.postgres-spec.ts`, `crm-audit-import-matching-deferred-runner.postgres-spec.ts`, `crm-audit-membership-cleanup.postgres-spec.ts`: 4 реальных PostgreSQL-сценария жизненного цикла и инвариантов `ShareWithService` (Branch A с реальным `assertNativeCrmAuditWriteSupported` + Branch B `user`/имперсонация/`apiKey`/`application`+`actingAgent`/`system`, общий `correlationId`) и `WorkflowRunRecordShareService` (имперсонатор, идемпотентный no-op, понижение видимости с сохранением неуправляемых `MANUAL`, deferred handler, fail-closed и rollback при сбое flush / post-flush drift).
