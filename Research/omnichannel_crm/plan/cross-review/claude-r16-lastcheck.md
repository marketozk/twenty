# Проверка C5: закрыто

Очистка после публикации политики теперь явно не трогает pending-ответы менеджеров.

## Что проверено в тексте

- **Очистка:** в `access-control.md:27` записано: «создаёт cancel outbox только для non-human Commands (senderClass ≠ human)». Остальной текст абзаца не изменился: запрет по версии head проверяется сразу после публикации (non-human), действует и без scanner, синхронного обхода всех диалогов нет.
- **Тест:** туда же добавлено условие T10/T14/T19/T27: «pending human Command после publish не отменяется этой cleanup (её текущие grants всё равно проверяются)».
- **Индекс:** в `implementation-spec.md:56` у OutgoingCommand частичный индекс `(workspaceId, policyId, policyVersion, state, id) WHERE senderClass != human` — тот же признак, что в правиле очистки.

## Прямые противоречия

Не нашёл. Новое правило согласуется со всеми соседними местами:
- `spec:95`: пара политики у human-команды хранится только как происхождение; точная проверка версии касается только non-human.
- `spec:107`: reference обязателен только для non-human Commands.
- P14 в `decision-tables.md:74`: проверка версии ограничена non-human.
